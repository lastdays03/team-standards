## 2. 강점 분석

### 2-1. skill-rules.json 기반 자동 활성화 시스템

가장 차별화된 핵심 자산이다. 20개+ 스킬에 대해 4가지 트리거 유형을 정의:

```
keywords      → 명시적 키워드 매칭 ("fastapi", "pytest")
intentPatterns → 정규식 기반 의도 감지 (".*test.*backend.*")
filePathTriggers → 글로브 패턴 파일 매칭 ("backend/**/*.py")
contentPatterns → 파일 내용 기술 감지 ("from fastapi import")
```

이 시스템은 사용자가 스킬을 수동으로 호출할 필요 없이, 프롬프트와 파일 컨텍스트만으로 관련 스킬을 자동 주입한다. 대부분의 Claude Code 프로젝트에서 이 수준의 자동화는 구현하지 않는다.

### 2-2. Progressive Disclosure 패턴

Anthropic의 500줄 규칙을 체계적으로 적용:
- SKILL.md: 핵심 가이드라인 (500줄 이내)
- resources/: 상세 참조 파일 (필요 시에만 로드)
- fastapi 스킬 예시: 메인 1,900줄 + 리소스 9개 → 컨텍스트 윈도우 효율적 사용

### 2-3. 실전 검증된 패턴

QWarty 프로젝트(FastAPI + Next.js 15)에서 2.5주+ 운영하며 검증된 패턴:
- Context Memory 크기 가이드 (dev-status 50줄, handoff 40줄)
- 기획(planning) vs 구현(dev) 문서 분리 원칙
- 세션 시작/종료 체크리스트
- 작업 단위 변경 로깅 루틴

### 2-4. 메타 스킬 (skill-developer)

스킬을 만드는 방법을 가르치는 스킬이 포함되어 있다:
- 트리거 패턴 라이브러리
- 훅 메커니즘 가이드 (exit code 동작 설명)
- 트러블슈팅 가이드
- 500줄 규칙 적용 방법

이는 템플릿의 **자기 확장성**을 보장한다 — 새 프로젝트에서 커스텀 스킬을 추가할 때 가이드 역할.

### 2-5. 설치 스크립트의 즉시 사용 가능성

```bash
curl -fsSL https://...install-claude-env.sh | bash -s -- ~/target-project
```

한 줄로 .claude/, CLAUDE.md, 훅 의존성까지 설치 완료. 백업 전략 포함.

## 3. 약점 및 개선 필요 사항

### 3-1. 기술 스택 종속성 (Critical)

| 문제 | 영향 | 심각도 |
|------|------|--------|
| fastapi/nextjs 스킬이 전체의 35%+ 차지 | 다른 스택 프로젝트에서 즉시 사용 불가 | 높음 |
| auth-route 에이전트 2개가 JWT/쿠키 전용 | Express/Keycloak 외 프로젝트에서 무용 | 중간 |
| tsc-check 훅이 TypeScript 전용 | Python/Go 프로젝트에서 무효 | 중간 |

**현재 즉시 사용 가능 비율**: 전체 자산의 약 **55-60%** (범용 스킬 6개 + 범용 에이전트 7개 + 커맨드 2개 + 훅 시스템)

### 3-2. 스킬 버전 관리 부재

- 스킬이 의존하는 라이브러리 버전 추적 없음 (예: Next.js 15 스킬이 Next.js 14에서도 유효한지?)
- 스킬 변경 이력 관리 = git log 의존
- 다중 프로젝트 배포 시 버전 차이로 인한 혼선 가능

### 3-3. 스킬 간 의존성 미정의

- pytest-backend-testing이 fastapi-backend-guidelines의 패턴에 의존
- error-tracking이 특정 프레임워크 패턴 가정
- 의존성 그래프 없음 → 개별 스킬 제거 시 영향 범위 불명

### 3-4. 설치 후 커스터마이징 가이드 부족

install-claude-env.sh 실행 후 필요한 작업:
1. skill-rules.json 경로 패턴 수정 (15-30분)
2. CLAUDE.md 프로젝트별 커스터마이징 (30-60분)
3. 불필요 스킬 비활성화 (10분)
4. 브랜드 가이드라인 교체 (가변)

→ CLAUDE_INTEGRATION_GUIDE.md가 있으나, **체크리스트 형태의 퀵스타트**가 부족

### 3-5. 테스트/검증 프레임워크 없음

- 스킬이 올바르게 트리거되는지 검증하는 방법 없음
- 훅이 정상 작동하는지 통합 테스트 없음
- skill-rules.json 문법 오류 검출 도구 없음

### 3-6. 분석/추적 없음

- 어떤 스킬이 실제로 활성화되었는지 로그 없음
- 어떤 트리거가 오탐(false positive)을 발생시키는지 추적 불가
- 스킬 효과 측정 불가
