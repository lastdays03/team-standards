## Architecture Highlights

1. **DB Read/Write Separation** — 읽기 전용 쿼리를 별도 세션으로 분리하여 확장성 확보. 트래픽 증가 시 읽기 레플리카 추가만으로 대응 가능.
2. **클라이언트 사이드 이미지 압축** — S3 업로드 전 브라우저에서 WebP 변환 및 압축. 서버 부하 없이 이미지 최적화 달성 (최대 50MB 지원).
3. **DDD 도메인 구조** — 11개 도메인(user, auth, artist, artwork 등)이 model/service/repository로 분리. 기능별 독립 개발 및 테스트 가능.

## Risks & Dependencies

- **Firebase Auth 의존성** — 소셜 로그인이 Firebase에 전적으로 의존. 장애 시 신규 로그인 차단. Fallback 로그인 검토 중.
- **AI 비용 증가** — Curai 사용량 증가 시 LLM API 비용 선형 증가. 캐싱 및 요청 최적화로 대응 예정.
- **단일 리전 배포** — 현재 ap-northeast-2 단일 리전. 글로벌 사용자 확장 시 멀티 리전 또는 CDN 전략 필요.
